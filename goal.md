## Project Title
Design and Development of a Model for Early Detection of Plant Health in
*Rosa-sinensis* using Leaf Vein Architecture

## Core Problem
Nutrient deficiencies in *Rosa-sinensis* (hibiscus) show early, subtle signs — mild
discoloration and changes in leaf vein density/thickness — long before visible damage
(strong yellowing, leaf drop) appears. Manual inspection is subjective and unreliable;
lab-based soil/tissue testing is accurate but slow, costly, and impractical for routine
home/campus monitoring. There is no simple, non-invasive, low-cost way for a
non-expert to catch this early.

## What We Are Building
A **rule-based, classical image-processing system** (explicitly **no machine learning
model / no trained classifier**) that takes a single leaf image and outputs a health
verdict — Healthy / Possibly Deficient / Deficient — along with the specific features
that drove the verdict, so the result is interpretable and traceable to real botanical
signals (not a black box).

## Non-Negotiable Constraints
1. **No ML / no training pipeline.** No neural networks, no scikit-learn classifiers, no
   "train/test split" of a labeled dataset for prediction purposes. Feature extraction
   thresholds may be *calibrated* from a small reference sample of known-healthy leaves,
   but the decision logic itself must be explicit, human-readable rules/formulas
   (if-then, index comparisons, statistical z-score bands) — not a learned model.
2. **Non-invasive.** Only a photograph of the leaf is used as input. No soil sampling,
   no tissue sampling.
3. **Low-cost / accessible.** Must work with a smartphone camera and commonly available,
   free/open-source software (Python + OpenCV + NumPy). No paid APIs, no cloud ML
   services required for the core pipeline.
4. **Interpretable output.** Every verdict must be explainable in plain language:
   which feature(s) were out of range and what that typically indicates
   (e.g., "vein density 18% below healthy baseline + inter-veinal yellowing →
   pattern consistent with nitrogen/magnesium deficiency").
5. **Single species scope for Phase-II.** *Rosa-sinensis* only. No generalization claims
   to other species in this phase.
6. **Backlit/transmitted-light capture is mandatory**, not optional, for any image that
   feeds the vein-extraction stage. Veins are not reliably visible in normal front-lit
   photos — this is a hard requirement of the capture protocol, not a nice-to-have.
7. **Ground truth must exist for every reference/calibration leaf.** Each leaf used to
   set thresholds or validate the system must have a documented basis for its
   "healthy" / "deficient" label (visual expert grading against a known symptom
   reference chart, at minimum — lab testing if available, but not required to hit
   the non-invasive/low-cost goals above).

## Novelty Positioning (confirmed via literature search, 2026-08-20)
This project's novelty rests on two gaps found in a search of the existing
nutrient-deficiency image-analysis literature, and both must be preserved by any
future change to this plan:
1. **Species gap** — no published work applies image-based nutrient-deficiency
   detection to *Hibiscus rosa-sinensis*. Existing image-analysis studies target
   food/commercial crops (rice, mango, grape, citrus, coffee, tomato, black gram,
   apple). Hibiscus literature that exists is plant-physiology research (e.g.
   potassium/drought response), not image-based detection.
2. **Methodology gap** — the field is dominated by ML/DL classifiers (SVM, CNN,
   neural nets) trained on labeled datasets. A handful of papers use classical vein/
   edge detection (e.g. Canny), but only as a preprocessing step feeding into an ML
   classifier — not as a standalone, transparent, threshold-based decision engine
   that reports *which* feature crossed *which* threshold. Keeping this project
   rule-based and interpretable (per the Non-Negotiable Constraints above) is what
   preserves this gap — reverting to an ML classifier would collapse the project
   back into a crowded, non-novel category.

Any future revision to `implementation_plan.md` must be checked against these two
points before being adopted, and any such check should be logged in `changes.md`.

## Success Criteria (Definition of Done for Phase-II)
- [ ] A documented, repeatable leaf image capture protocol (backlighting setup,
      distance, background, resolution) that a non-expert can follow.
- [ ] A labeled reference dataset of ≥60 *Rosa-sinensis* leaf images (mix of healthy
      and visibly/subtly deficient), each with a documented ground-truth basis.
- [ ] A working pipeline: image → preprocessing → leaf segmentation → vein
      extraction/skeletonization → feature extraction (vein density, vein thickness,
      color/chlorosis indices) → rule-based decision engine → human-readable report.
- [ ] Threshold/rule calibration derived transparently from the healthy-leaf subset of
      the reference dataset (documented, not hidden inside code).
- [ ] Validation of the rule engine against the held-out portion of the reference
      dataset, reported as accuracy/precision/recall **of the rule engine**, with a
      confusion matrix — explicitly not framed as "model accuracy" since there is no
      trained model.
- [ ] A simple interface (CLI acceptable minimum; a basic web/GUI upload-and-report
      view is a stretch goal) where a user submits an image and receives the report.
- [ ] All findings, limitations, and false positive/negative cases documented for the
      Phase-II report writeup and viva defense.

## Explicitly Out of Scope
- Any species other than *Rosa-sinensis*.
- Mobile app deployment (may be mentioned as future work only).
- Any deep learning / CNN-based classification, even as a "comparison baseline" —
  keep the whole project ML-free per constraint #1.
- Multi-leaf / whole-plant analysis (single leaf image per assessment only).

## Reference Vocabulary (used consistently across plan & changes)
- **Deficiency pattern**: a named nutrient-deficiency symptom class (e.g., nitrogen —
  uniform yellowing of older leaves; magnesium — interveinal chlorosis with veins
  staying green; iron — interveinal chlorosis on younger leaves with fine veins) used
  only as *descriptive labeling* for report language, not as an ML class.
- **Reference/calibration set**: the labeled leaves used to set numeric thresholds.
- **Validation set**: leaves held out from calibration, used only to check the rule
  engine's output against ground truth.
